# プロパ人材管理機能 設計書

**日付**: 2026-06-04  
**ステータス**: 承認済み

---

## 概要

自社プロパ社員の人材情報をVatchで管理できるようにする。プロパは外部タレントと同じマッチング対象として扱いつつ、専用の管理画面とプロパ本人向けポータルを提供する。東京・名古屋の拠点区別、経歴書（Word文書）からのAI自動データ抽出、お気に入り案件保存機能を含む。

---

## 1. データモデル設計

### 1-1. Talent モデルへの追加フィールド

```prisma
model Talent {
  // 既存フィールドはそのまま維持
  talentType  TalentType  @default(EXTERNAL)
  office      Office?                         // プロパのみ設定
  userId      String?     @unique             // プロパ本人のUserアカウントへの紐付け

  properUser  User?       @relation("ProperUser", fields: [userId], references: [id])
}

enum TalentType {
  PROPER
  EXTERNAL
}

enum Office {
  TOKYO
  NAGOYA
}
```

- `EXTERNAL`（既存）: 外部から送られてくるタレント。`office` は null、`userId` は null。
- `PROPER`（新規）: 自社プロパ社員。`office` に拠点を設定、`userId` でログインアカウントと紐付け。

### 1-2. Role への追加

```prisma
enum Role {
  ADMIN
  STAFF
  PROPER  // 追加
}
```

- `PROPER` ロールのユーザーはポータル画面のみアクセス可能。
- 管理画面（`/proper`, `/talents`, 等）へのアクセスは不可。

### 1-3. Favorite モデル（新規）

```prisma
model Favorite {
  id        String   @id @default(cuid())
  userId    String
  caseId    String
  user      User     @relation(fields: [userId], references: [id])
  case      Case     @relation(fields: [caseId], references: [id])
  createdAt DateTime @default(now())

  @@unique([userId, caseId])
}
```

## 2. 機能設計

### 2-1. 経歴書アップロード → AI自動抽出

1. 管理者が拠点（東京/名古屋）を選択し、Word文書（.doc/.docx）をアップロード
2. サーバーサイドで mammoth.js を使いWord文書からテキスト抽出
3. Claude API に送信し、以下の構造化データを抽出:
   - 名前、スキル（配列）、経験年数、希望単価、稼働状況、メールアドレス
4. 確認フォームに抽出結果をプレビュー表示（全フィールド編集可能）
5. 「登録」で以下を同時作成:
   - `Talent` レコード（talentType: PROPER, office: 選択した拠点）
   - `User` レコード（role: PROPER, 仮パスワード生成）
6. 登録完了画面でログイン用メールアドレスと仮パスワードを表示

### 2-2. 管理者によるプロパアカウント管理

- 管理者・スタッフのみアクセス可能
- プロパ情報の編集（スキル・単価・稼働状況など）
- パスワードリセット（仮パスワード再発行）

### 2-3. プロパ向けポータル（本人ログイン時）

- プロパが自分のスキル・条件に合う案件を閲覧
- ログインユーザーに紐付く Talent レコードを特定し、そのタレントに対して既に生成された Matching レコードをスコア順に表示（マッチング生成自体は管理者側の既存フローを使用）
- お気に入りボタンで Favorite レコードを作成・削除
- `/portal/favorites` でお気に入り案件のみ表示

## 3. 画面設計

### 3-1. サイドナビへの追加

```
ダッシュボード
案件
タレント
プロパ管理  ← 新規追加（ADMIN/STAFFのみ表示）
マッチング
契約
```

### 3-2. /proper — プロパ一覧

- 東京/名古屋タブで切り替え
- 一覧列: 名前 / スキル / 稼働状況 / 希望単価 / 登録日
- 「＋ プロパを登録」ボタン

### 3-3. /proper/new — 新規登録

```
Step 1: 拠点選択（東京 / 名古屋）
Step 2: 経歴書アップロード（.doc / .docx）
        → AI解析中スピナー
Step 3: 確認・編集フォーム
        名前 / スキル / 経験年数 / 希望単価 / 稼働状況 / メールアドレス
Step 4: 登録完了 → ログイン情報表示
```

### 3-4. /proper/[id] — プロパ詳細・編集

- 基本情報の編集
- 稼働状況・単価の更新
- パスワードリセットボタン

### 3-5. /portal — プロパ向けポータル

- ログインしたプロパ本人のみアクセス可能
- マッチスコア順に案件カード表示
- 各カードに「♡ お気に入り」トグルボタン
- タブ: 「すべての案件」「お気に入り」

---

## 4. 認証・認可

| ロール | アクセス可能範囲 |
|--------|----------------|
| ADMIN | 全画面 |
| STAFF | 全管理画面（/proper 含む）|
| PROPER | /portal のみ |

- ミドルウェアで `PROPER` ロールが `/portal` 以外にアクセスしようとした場合は `/portal` にリダイレクト
- 管理画面は `PROPER` ロールからのアクセスを拒否
